# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**
- Пользователи могут включать и отключать отопление в доме
- Система позволяет:
	- получить список всех устройств по локации
	- зарегистрировать новое устройство (только сенсор, только специалистом)
	- обновить информацию по датчику 
	- удалить датчик

**Мониторинг температуры:**
- Пользователи могут проверять температуру в доме
- Система позволяет:
	- проверить температуру по конкретному датчику и по всей локации (дому)
	- просмотреть температуру в доме через веб-интерфейс

### 2. Анализ архитектуры монолитного приложения

Язык программирования: Golang
База данных: postgresql
Архитектура: монолитная
Взаимодействие: синхронное взаимодействие (температура датчика запрашивается синхронно при запросе данных о самом датчике)
Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям.
Развертывание: Требует остановки всего приложения.


### 3. Определение доменов и границы контекстов
- Домен: управление отоплением
	- поддомен: управление устройствами
		- контекст: управление устройствами (регистрация, привязка к локации, получение)
	- поддомен: взаимодействие с устройствами
		- контекст: отправка команд
		- контекст: получение температуры с устройств

### **4. Проблемы монолитного решения**
- Единая точка отказа и сложность масштабирования:
	- единое приложение для взаимодействия с датчиками и для пользовательского управления
- Единая точка редеплоя
	- например, при добавлении устройства нового производителя придется редеплоить пользовательскую часть
- Общая кодовая база для разных бизнес-процессов может создать ошибки из-за связанности

# Задание 5. Работа с docker и docker-compose

Перейдите в apps.

Там находится приложение-монолит для работы с датчиками температуры. В README.md описано как запустить решение.

Вам нужно:

1) сделать простое приложение temperature-api на любом удобном для вас языке программирования, которое при запросе /temperature?location= будет отдавать рандомное значение температуры.

Locations - название комнаты, sensorId - идентификатор названия комнаты

```
	// If no location is provided, use a default based on sensor ID
	if location == "" {
		switch sensorID {
		case "1":
			location = "Living Room"
		case "2":
			location = "Bedroom"
		case "3":
			location = "Kitchen"
		default:
			location = "Unknown"
		}
	}

	// If no sensor ID is provided, generate one based on location
	if sensorID == "" {
		switch location {
		case "Living Room":
			sensorID = "1"
		case "Bedroom":
			sensorID = "2"
		case "Kitchen":
			sensorID = "3"
		default:
			sensorID = "0"
		}
	}
```

2) Приложение следует упаковать в Docker и добавить в docker-compose. Порт по умолчанию должен быть 8081

3) Кроме того для smart_home приложения требуется база данных - добавьте в docker-compose файл настройки для запуска postgres с указанием скрипта инициализации ./smart_home/init.sql

Для проверки можно использовать Postman коллекцию smarthome-api.postman_collection.json и вызвать:

- Create Sensor
- Get All Sensors

Должно при каждом вызове отображаться разное значение температуры

Ревьюер будет проверять точно так же.
Решение:
1. Файлы созданы, но модифицированы в связи с 6 заданием
2. Для запуска нужно создать файл .env в папке `apps/` со своими значениями паролей и логинов:
```
POSTGRES_PASSWORD=postgres //for monolith
POSTGRES_USER=postgres //for monolith
DEVICE_POSTGRES_PASSWORD=postgres
DEVICE_POSTGRES_USER=postgres
TELEMETRY_POSTGRES_PASSWORD=postgres

```

# **Задание 6. Разработка MVP**

Необходимо создать новые микросервисы и обеспечить их интеграции с существующим монолитом для плавного перехода к микросервисной архитектуре. 

### **Что нужно сделать**

1. Создайте новые микросервисы для управления телеметрией и устройствами (с простейшей логикой), которые будут интегрированы с существующим монолитным приложением. Каждый микросервис на своем ООП языке.
2. Обеспечьте взаимодействие между микросервисами и монолитом (при желании с помощью брокера сообщений), чтобы постепенно перенести функциональность из монолита в микросервисы. 

В результате у вас должны быть созданы Dockerfiles и docker-compose для запуска микросервисов. 
**Решение: **
1. созданы микросервисы device-service, telemetry-service
2. метод создания датчика в монолите вызывает метод создания девайса в device-service
3. telemetry-service выдает рандомные показатели метрик в соответствии с типом устройства
4. device-service интегрирован с telemetry-service в методе получения списка девайсов
